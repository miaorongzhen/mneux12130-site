# 凡骨问道正式项目迁移简报

## 定位

《凡骨问道》当前网页是玩法实验台，不是最终工程。正式项目应保留已经验证的文字修仙战斗养成循环，重新按长期可维护项目拆分数据、战斗、成长、存档和界面。

目标体验：玩家从凡人起步，通过探索、境遇抉择、战斗、门派委托、试炼、功法、构筑、神通、丹符和心魔风险，把一个小人物培养到列名外门。

## 已验证核心循环

```text
探索地图
-> 触发战斗或境遇抉择
-> 战斗胜利进入战后抉择
-> 获得修为、材料、贡献、血玉、残页等资源
-> 资源转化为功法、装备、神通、丹符、门派身份
-> 推进外山试炼和突破
-> 控制心魔风险或迎战心魔劫
-> 最终完成外门试炼
```

## 当前系统清单

- 角色数值：气血、真气、修为、心魔、战力、攻击、防御、身法、声望。
- 境界：凡人、炼体、练气。
- 资源：银钱、药材、残页、血玉、矿石、灵石、贡献。
- 丹符：回春丹、回气丹、护身符。
- 地图：村外荒林、破庙、乱葬岗、黑风岭、青云山道、残碑幻境。
- 战斗：普通攻击、催动功法、守势回气、血玉邪力、丹符使用。
- 状态：流血、中毒、眩晕、封气、破绽、护体、蓄势、狂暴。
- 功法：青木吐纳诀、山石护体功、青锋三式、踏云步、血玉残法。
- 构筑：剑修破绽流、青木续航流、山石防反流、血玉爆发流。
- 神通：青木生脉、山纹反照、青锋留痕、踏云避劫、血玉回响、残碑定息。
- 门派：青云杂役、青云外山记名、青云外门。
- 委托：药庐供奉、巡山除患、镇压阴祟、残碑看守。
- 试炼：一阶问心、二阶校场、三阶灵兽、四阶残碑、最终外门试炼。
- 风险：心魔高位触发心魔幻身，镇心调息可主动降压。
- 指引：道途指引根据当前状态给出下一步优先事项。

## 正式项目拆分建议

正式工程不要继续扩大单个 `index.html`。应拆为这些模块：

- `GameState`：角色、资源、地图、门派、功法、神通、试炼、待处理决策。
- `CombatSystem`：回合结算、状态、敌人特性、胜败分支。
- `GrowthSystem`：境界、功法、构筑评分、神通领悟、装备锻造。
- `DecisionSystem`：战后抉择、境遇抉择、心魔劫触发。
- `ContentData`：地图、敌人、事件、委托、试炼、功法、神通表。
- `SaveSystem`：版本化存档和旧存档迁移。
- `UI`：角色面板、行动面板、地图、委托、试炼、构筑、神通、日志、指引。
- `SmokeTests`：保持当前核心循环验证，不随手工试玩漂移。

## 引擎边界

当前不锁定 Godot、Unity 或 Cocos。正式迁移前应先用这份实验台验证玩法闭环，再根据目标平台、开发工具链、UI复杂度、发布路径和维护成本做引擎决策。

临时判断：如果继续以网页实验台验证玩法，保留静态 HTML 即可；如果进入正式长期开发，应新建独立项目，不把当前单文件继续硬扩成正式工程。

## 迁移入口条件

满足以下条件后，可以创建正式项目：

- 网页实验台核心循环 smoke test 通过。
- 外门前阶段的资源循环不再出现明显死路。
- 至少一条正道路线和一条邪法路线都能通到外门试炼。
- 用户明确授权创建正式项目目录和选择/试用引擎。
- 正式项目第一版只迁移外门前闭环，不扩到内门、金丹、开放世界或大量剧情。

## 验证门槛

当前 smoke test：

```powershell
npm run smoke
```

覆盖范围：页面渲染、旧存档迁移、境遇抉择、丹符整备、战斗丹符、战败结算与失败后继续行动、心魔劫、镇心调息、炼体突破、练气突破、药材委托转贡献并晋升记名、灵石炼化转修为、乱葬岗产出血玉和残页并增加心魔压力、黑风岭产出矿石、青云山道产出贡献、残碑幻境产出灵石和残页、外山试炼推进、正道路线最终外门试炼通关、血玉邪法路线最终外门试炼通关。

资源死路要求：外门前闭环必须证明药材、残页、血玉、矿石、灵石、贡献、丹符和心魔压力都能被稳定获得、消耗和转化。正式项目迁移后，自动验证不能只放一个满资源终点存档，还要覆盖关键资源来源、门槛消耗与身份推进。

失败回收要求：正式项目必须保留战败后的可继续状态，至少验证战败会清除战斗、恢复最低可玩气血/真气、扣除部分修为、增加心魔，并且玩家可以通过疗伤、静修或镇心调息回到养成循环。失败不能变成软锁，也不能被设计成只有胜利路线才可玩。

存档要求：正式项目必须保留版本号和迁移函数。新增系统时不能只做浅合并，嵌套字段如功法、装备、神通、丹符、待处理抉择和战斗状态都要有默认值补齐。

正式项目迁移后，第一条自动验证也应覆盖同样闭环，而不是只检查启动成功。
